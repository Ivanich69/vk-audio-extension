# VK Audio — расширение для сохранения аудио

Версия 0.3.12 для Chrome 120+ и совместимых браузеров на Chromium (включая Яндекс Браузер). Проверена на Chrome 156.0.8078.48 с локальными тестовыми ответами; реальный аккаунт VK в автоматических проверках не использовался. JavaScript, Manifest V3. Совместимость с конкретной версией Яндекс Браузера отдельно не проверялась.

Расширение обнаруживает записи в ответах музыкальных запросов VK, включая `catalog.getSection`, и аудиовложения в `messages.getHistory`: получает вместе `artist`, `title`, `duration`, `url`, `owner_id` и `id`. Поэтому имя файла берётся из самого трека, например `Исполнитель — Название.mp3` для MP3. Ссылки без расширения учитываются; перед сохранением формат определяется по байтам полученного файла.

## Установка

1. Скачай установочный ZIP из [Releases](https://github.com/Ivanich69/vk-audio-extension/releases) и распакуй в отдельную папку. Также можно клонировать этот репозиторий и использовать его корневую папку.
2. Открой `chrome://extensions` в Chrome или `browser://extensions` в Яндекс Браузере.
3. Включи «Режим разработчика», нажми «Загрузить распакованное расширение» и выбери папку, где лежит `manifest.json`.
4. Перезагрузи открытую страницу ВКонтакте и открой «Моя музыка», поиск или плейлист. Если нужная запись не появилась, включи её: VK может дополнительно загрузить ссылку при воспроизведении.
5. Нажми стрелку **↓** рядом с нужным треком на странице VK. В строках с панелью действий она находится рядом с остальными кнопками и может появляться при наведении на строку. Также можно открыть VK Audio через меню расширений, нажать «Обновить», затем «Скачать» рядом с нужным источником.

Любой источник, включая прямой MP3, открывается в отдельной вкладке со статусом загрузки и проверкой формата. По умолчанию она открывается в фоне и закрывается после успешного сохранения. После получения аудио браузер покажет окно выбора места сохранения. Если нужны дополнительные серверы, разреши их по кнопке в этой вкладке. Не закрывай её вручную, пока загрузка не завершена.

При обновлении замени файлы в установленной папке и нажми кнопку перезагрузки расширения на странице расширений. В заголовке popup должна появиться версия **0.3.12**. Перезагрузи VK и заново открой загрузку: старые страницы VK и вкладки загрузки используют старый код.

## Автозакрытие после сохранения — версия 0.3.12

Вкладка загрузки автоматически закрывается после подтверждения успешного сохранения файла менеджером загрузок Chrome. Это работает для прямого аудио, HLS и явно выбранного сохранения исходного TS. Закрывается только сама вкладка загрузки; выбранная пользователем вкладка VK не затрагивается. Получение аудио с сервера и открытие диалога сохранения ещё не считаются завершением.

При отмене, ошибке, запросе доступа или неудаче извлечения аудио вкладка остаётся открытой. Если Chrome не позволит её закрыть, останется сообщение об успешном сохранении и возможности закрыть вкладку вручную. Опция **«Настройки загрузки» → «Закрывать вкладку после сохранения»** включена по умолчанию; её можно отключить, чтобы оставить страницу с результатом и кнопкой повторного сохранения. Выбор применяется к новым вкладкам загрузки.

## Загрузка без переключения с VK — версия 0.3.11

В popup добавлены **«Настройки загрузки» → «Открывать загрузку в фоне»**. По умолчанию опция включена: нажатие стрелки рядом с треком или кнопки «Скачать» создаёт неактивную вкладку загрузки, оставляя текущую вкладку выбранной. Если отключить опцию, новые загрузки снова открываются с переключением на них. Выбор хранится локально и сохраняется после закрытия popup и перезапуска браузера.

Вкладка остаётся видна в панели вкладок; полностью скрытая загрузка без вкладки в этой версии не реализована. В ней доступны прогресс, ошибки, повторная попытка, сохранение TS и разрешения для новых серверов. Не закрывай её до окончания загрузки. Окно выбора места сохранения файла появляется как прежде; фоновой настройкой оно не отключается. Настройка применяется к новым загрузкам, уже открытые вкладки не переключаются.

Создание неактивной вкладки использует параметр `active: false` в [Chrome Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-create) и не требует новых разрешений расширения.

## Доступ к аудиосерверам без отдельных запросов — версия 0.3.10

Добавлено постоянное HTTPS-разрешение для `vkuseraudio.ru` и всех его поддоменов. Серверы вроде `cs1-77v4.vkuseraudio.ru`, `cs9-5v4.vkuseraudio.ru` и `psv4.vkuseraudio.ru` теперь доступны без отдельного подтверждения на каждый сервер. Это относится к файлам, плейлистам, сегментам и ключам AES-128 на этих доменах. Проверки фактически выданных прав сохраняются: если доступ ограничен в настройках Chrome, расширение предложит его разрешить.

При обновлении Chrome может один раз запросить подтверждение новых прав; после этого перезагрузи VK и открой новую вкладку скачивания. Для серверов вне перечисленных доменов остаётся отдельный запрос. Скрипты обнаружения по-прежнему внедряются только на страницы VK. Такое объявление доступа описано в [документации Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions).

## Ошибка заголовка MPEG Audio — версия 0.3.9

Проверка MP3 теперь учитывает теги ID3v2.2/2.3/2.4 на границах кадров и завершающий ID3v1. Проверяются длина, версия, флаги и соответствие footer заголовку; сами метаданные сохраняются без изменений. Произвольные байты и повреждённые кадры не пропускаются. Формат заголовка и footer описан в [спецификации ID3v2.4](https://id3.org/id3v2.4.0-structure).

Если извлечение всё же останавливается, раскрой **«Диагностика извлечения аудио»** и скопируй текст. В нём версия, размеры, тип дорожки, позиция ошибки и количество проверенных кадров; ссылок, ключей, названий и содержимого тегов нет. По одному скриншоту нельзя определить точную причину ошибки конкретного трека; наличие ID3 в пользовательском потоке пока не подтверждено. `Unknown artist — Untitled` — отдельная проблема метаданных, эта версия её не исправляет.

После получения всех частей TS доступна кнопка **«Сохранить исходный TS»**, если извлечь MP3/AAC не получилось. Она сохраняет уже загруженные и, при AES-128, расшифрованные части без повторных запросов. Это явное сохранение контейнера `.ts`; его воспроизводимость зависит от плеера и целостности данных. При ошибке сети, ключа или неполной загрузке кнопка не появляется. «Повторить извлечение аудио» заново загружает поток по прежней ссылке.

Для этого TS-части удерживаются до завершения извлечения; расход памяти может превышать размер исходного потока. Лимит входных данных остаётся 256 МБ. Автоматические проверки используют сгенерированные MP3/AAC-потоки: успешное извлечение сравнивается по байтам, а MP3 с ID3 дополнительно декодируется FFmpeg. Реальный трек со скриншота не анализировался.

## «Пустой транспортный пакет» — исправление 0.3.8

Добавлена совместимость с TS-пакетами, у которых установлен флаг полезных данных (AFC=3), но служебное поле адаптации занимает всё оставшееся место: 183 байта после поля длины. В предыдущих версиях такой пакет немедленно останавливал извлечение аудио. Теперь он учитывается в последовательности транспортных пакетов, но не добавляет аудиобайтов и не разрывает текущий PES или таблицу потока. Это обработка несовпадения флага и фактического содержимого; обычные пакеты только с полем адаптации поддерживались и ранее.

Проверки потерянных пакетов, выхода поля адаптации за границы пакета, разрывов потока и обрезанных аудиокадров сохраняются. Новая версия не пропускает произвольные ошибки TS. Обнови расширение и начни загрузку в новой вкладке: кнопка «Повторить» в старой вкладке использует старый код.

В тестах исходная ошибка воспроизведена добавлением таких пакетов в MP3/AAC-потоки, включая повторные пакеты, флаг начала полезных данных, переход счётчика через 15 и границы HLS-сегментов. FFmpeg независимо извлекает из этих потоков те же байты, что из исходных файлов. Браузерная проверка проходит также после AES-128-шифрования сегментов. Реальный файл трека «10AGE — Так нужно» не анализировался: исходным материалом был скриншот ошибки.

## Вместо MP3 предлагался HTML — исправление 0.3.7

До 0.3.7 прямые ссылки с расширением `.mp3` передавались браузеру без проверки ответа. По такой ссылке сервер мог вернуть HTML-страницу ошибки или авторизации; также заголовки сервера могли ошибочно указывать HTML для настоящего аудио. Один лишь диалог с расширением `.htm` не позволяет различить эти случаи.

Теперь прямые файлы и ссылки без расширения проходят один GET-запрос с ограничением 256 МБ. Тип определяется по содержимому. HTML/XML, JSON и нераспознанные ответы останавливаются с ошибкой до окна сохранения; текст ответа и подписанный URL в ошибку не выводятся. Настоящий MP3 с ошибочными `Content-Type: text/html` или `Content-Disposition: filename=…htm` сохраняется как MP3 с именем из метаданных трека. HLS, пришедший по адресу с `.mp3`, обрабатывается как HLS.

В менеджер загрузок передаются уже проверенные байты через Blob с соответствующим MIME, а не исходный адрес. Поэтому между проверкой и сохранением нет второго запроса по временной ссылке. Проверка определяет формат по сигнатуре; она не является полным декодированием каждой аудиодорожки.

Если новая версия сообщает, что вместо аудио пришла страница, включи трек заново и снова нажми стрелку рядом с ним. Это создаст задание из актуальной найденной ссылки; «Повторить» в старой вкладке повторяет прежний адрес. Доступность конкретной записи на сервере расширение гарантировать не может. Переименование HTML-файла в MP3 не восстанавливает аудио.

## Кнопка рядом с треком — версия 0.3.6

Стрелка добавляется к строкам `.audio_row`, `[data-audio]` и `[data-audio-id]`, включая подгружаемые при прокрутке записи. Привязка использует идентификатор из `data-full-id`, `data-audio-id`, `id="audio…"` или массива `data-audio`; при наличии явного URL внутри строки можно использовать его. Названия для сопоставления не используются: разные записи могут называться одинаково. При повторной отрисовке кнопка восстанавливается, при смене записи в строке привязка пересчитывается.

Неактивная стрелка означает, что для этой строки ещё нет подходящей ссылки. Наведи указатель, чтобы увидеть подсказку, затем включи трек и дождись активации кнопки. Дополнительных музыкальных API-запросов ради кнопок расширение не делает. Если обычный захват не видит ответа, сохраняется резервный способ через открытые DevTools и перезагрузку VK.

Нажатие стрелки не передаётся обычным обработчикам воспроизведения строки. Кнопка доступна с клавиатуры. Любой файл открывается во вкладке сохранения с проверкой содержимого. При необходимости доступ к аудиосерверу запрашивается кнопкой в этой вкладке.

Кнопка обрабатывает только доверенные события браузера: программный `.click()` и сообщения страницы не запускают скачивание. Фоновый обработчик проверяет одноразовое разрешение на нажатие в той же вкладке и документе, повторно получает запись и проверяет URL. В атрибуты кнопки не записываются подписанные ссылки и ключи доступа.

Если VK использует другую разметку, встроенная кнопка может отсутствовать или оставаться неактивной; список в popup продолжает работать. Реальный интерфейс VK конкретного аккаунта не входил в автоматические проверки.

## Если вместо музыки были только bb1.mp3, bb2.mp3, bb3.mp3

Эти файлы исключены из обычного обнаружения на доменах VK. Наличие таких источников само по себе не подтверждает получение ответа с каталогом музыки.

1. Обнови расширение до 0.3.8. Закрой и снова открой DevTools клавишей F12 **на вкладке VK**.
2. Не закрывая DevTools, перезагрузи VK и открой «Моя музыка» или нужный плейлист.
3. Открой popup расширения и нажми «Обновить». Должны появиться названия записей из музыкальных ответов.

Резервный режим получает тела ответов непосредственно из журнала Network через DevTools API. Он работает, пока открыты DevTools; выбирать специальную панель или вручную искать URL не нужно. Обычное обнаружение также работает без DevTools, если запросы проходят через обработчики страницы.

В popup есть «Диагностика обнаружения»: версия расширения и обработчика, число полученных и распознанных музыкальных ответов, число записей без подходящего URL, ошибки и состояние DevTools. В диагностике нет медиассылок, названий треков, заголовков запросов, ключей доступа или содержимого ответов. Если проблема повторяется, выдели этот текст кнопкой и скопируй его для разбора причины.

## Если найден только index.m3u8, а missingUrls больше нуля

Это означает, что расширение обнаружило поток, но не смогло получить подходящие прямые ссылки из прочитанных музыкальных ответов. `missingUrls` — число встреченных записей с неподходящим URL, а не число уникальных треков. В версии 0.3.1 оно разделено на `emptyUrls` (пустые/отсутствующие), `encodedUrls` (ссылки с `audio_api_unavailable`) и `invalidUrls` (остальные отклонённые значения). Значение `devtools.active: false` означает, что резервный захват не активен.

1. После обновления расширения обязательно перезагрузи страницу VK, включи нужную запись и обнови список.
2. Если доступно название через Media Session или видимый плеер VK, оно появится над списком как «В плеере: …».
3. У подходящего потока нажми «Взять название из плеера», затем «Скачать». Проверь, что выбрал поток именно этой записи. Название запоминается для этого источника и не меняется при переключении песни; если плеер переключился до нажатия кнопки, расширение попросит обновить список.

Обнаруженный HLS доступен для попытки скачивания и без названия, если он удовлетворяет ограничениям ниже. F12 нужен только для резервного чтения ответов. Исторические M3U8 не получают имя текущей песни автоматически: у потока в Resource Timing нет надёжной связи с текущими метаданными плеера. Имена из API сохраняют приоритет. Реальная разметка VK может отличаться от поддерживаемых селекторов; в таком случае название из плеера может отсутствовать.

Также в 0.3.1 исправлен счётчик ошибок: неудачные Fetch-запросы к посторонним методам больше не считаются ошибками музыкального перехвата. Поддержаны медиассылки вида `//сервер/путь` с использованием HTTPS.

## Аудио из messages.getHistory — исправление 0.3.2

В версиях до 0.3.2 этот метод не входил в список разрешённых для обнаружения, поэтому даже при открытых DevTools расширение пропускало его ответ. Теперь из `response.items[].attachments[]` извлекаются вложения `type: "audio"` с объектом `audio`; также учитываются вложения в `fwd_messages` и `reply_message`. Экранированные в JSON слеши (`https:\/\/…`) разбираются автоматически. Ссылка с `.mp3?siren=1` распознаётся как MP3 с сохранением параметров URL.

После обновления перезагрузи расширение, закрой и снова открой F12, затем перезагрузи вкладку VK и открой переписку с нужным аудиовложением. Когда VK загрузит историю, нажми «Обновить» в расширении. Должны появиться исполнитель, название и длительность из `audio`, вместе с MP3-ссылкой. Можно использовать обычный перехват без F12; резервный DevTools-перехват читает также доступные ответы из текущего журнала Network.

Ответ истории локально разбирается для поиска аудиовложений. Текст сообщений, профили, остальные виды вложений, `access_key` и `track_code` не передаются в список, фоновой обработчик или диагностику. Текст сообщений не разбирается как JSON. Дополнительных запросов истории расширение не отправляет; остальные методы `messages.*` не добавлены в список обнаружения.

## Возможности и ограничения

### Извлечение MP3 и AAC из TS — версия 0.3.5

После загрузки и, при необходимости, расшифровки HLS расширение извлекает аудиодорожку из транспортного контейнера MPEG-TS. Исходный MP3 сохраняется как `.mp3`, AAC/ADTS — как `.aac`. Аудиокадры сохраняются без перекодирования и потери качества. Фактический формат показан во вкладке загрузки. Имя по-прежнему берётся из исполнителя и названия трека.

Обработка выполняется внутри расширения; внешний сервис FFmpeg не используется. Для гарантированного MP3 из исходного AAC нужно перекодирование, которого в этой версии нет. Fragmented MP4 сохраняется как `.mp4`.

Поддержана одна аудиодорожка MPEG Layer III или AAC/ADTS в одной программе TS. Проверяются таблицы PAT/PMT и их CRC, последовательность транспортных пакетов, заголовки PES и границы аудиокадров. Повторные одинаковые пакеты не дублируют звук. При обнаружении повреждения, неподдерживаемого кодека, нескольких дорожек или смены формата сохранение останавливается с описанием причины. MPEG Layer II, AAC LATM и извлечение аудио из MP4 пока не поддерживаются.

### Вкладка «Музыка» — исправление 0.3.3

В диагностике 0.3.2 `encodedUrls: 74` при `found: 0` означало, что ссылки из `al_audio.php` отбрасывались из-за маркера `audio_api_unavailable`. Теперь такие ссылки локально декодируются перед добавлением в список. Поддержаны специальный Base64-алфавит VK и операции `v`, `r`, `x`, `s`, `i`; название, исполнитель, длительность и идентификатор берутся из той же записи API. Ответы каталога и музыкальные массивы `al_audio.php` используют один обработчик. Уже обнаруженный поток с совпадающим URL получает название без создания дубля.

1. Обнови файлы до текущей версии и перезагрузи расширение в `chrome://extensions`.
2. Обязательно перезагрузи страницу VK, открой «Музыка» и включи нужный трек.
3. Нажми «Обновить» в расширении. Для резервного режима закрой и снова открой F12, затем заново загрузи страницу/плейлист.

Для операции `i` нужен числовой ID текущего вошедшего пользователя (`window.vk.id`), а не владелец трека. Обычный обработчик читает его в контексте страницы; DevTools использует фиксированное выражение `Number(window.vk?.id) || 0` через `inspectedWindow.eval`. Это значение используется только в памяти для декодирования и не включается в диагностику, список треков или задания загрузки. Расширение не делает новых запросов API ради декодирования.

С версии 0.3.3 `encodedUrls` считает все встреченные закодированные ссылки, `decodedUrls` — успешно восстановленные, `decodeFailed` — нераспознанные, `needsUserId` — неудачи из-за отсутствия ID. `missingUrls` по-прежнему считает записи без подходящего итогового URL. Счётчики накопительные и могут учитывать один трек в нескольких ответах. Лимиты: URL 16 КиБ, до 16 преобразований и до 500 попыток декодирования на один ответ; неизвестные операции не выполняются.

Декодирование может вернуть MP3 или HLS — расширение сохраняет обнаруженный формат. Подстановка `.mp3` вместо `index.m3u8` не выполняется. Для HLS действуют ограничения ниже. Пользователь подтвердил обнаружение 74 именованных треков версией 0.3.3; автоматические проверки используют локальные тестовые ответы.

Алгоритм преобразований адаптирован из [исходного кода vk_api](https://github.com/python273/vk_api/blob/master/vk_api/audio_url_decoder.py); сведения об источнике и Apache-2.0 включены в архив. Дополнительные проверки сравнили шесть тестовых цепочек преобразований с исходной Python-реализацией.

### Остальные возможности

- Обнаружение объектов аудио в JSON-ответах `/method/catalog.*` и `/method/audio.*` на доменах VK, а также ответах `al_audio.php` и `al_catalog.php`. Поддерживаются Fetch, чтение `Response.json()`/`Response.text()`, XHR с текстом и JSON, вложенные JSON-строки и старые массивы аудиозаписей. JSONP разбирается как JSON-обёртка без выполнения кода. Записи из подходящих iframe VK передаются в основной список. Расширение не отправляет дополнительных запросов к музыкальному API.
- Независимое обнаружение через `chrome.devtools.network`, когда DevTools открыты: обработка новых ответов и доступных ответов из текущего журнала Network. Этот режим не зависит от того, сохранил или заменил сайт `window.fetch`.
- Аудиовложения из `/method/messages.getHistory` на доменах VK через те же Fetch, XHR и DevTools. Из истории сохраняются только нормализованные поля аудиовложения.
- Дополнительное обнаружение явных ссылок на MP3, M4A, AAC, OGG, OPUS, FLAC, WAV и M3U8 в сетевых ресурсах страницы и элементах аудио. Поддержан распространённый формат `audio_api_unavailable`; неизвестные варианты остаются в диагностике.
- Скачивание прямых файлов через вкладку проверки и штатный менеджер загрузок браузера; расширение файла определяется по содержимому ответа.
- HLS VOD без шифрования и с AES-128: аудиодорожки из master-плейлиста, MPEG-TS, AAC ADTS и fragmented MP4 с одним начальным сегментом. Из TS извлекаются MP3 или AAC; остальные поддержанные контейнеры сохраняются в исходном формате. Результат — `.mp3`, `.aac` или `.mp4` в зависимости от исходного аудио. Перекодирования и изменения качества нет.
- SAMPLE-AES, DRM, прямые эфиры, Byte Range, разрывы потока, смена начального сегмента и HTTP-перенаправления не поддерживаются. Для master-плейлистов без отдельной аудиодорожки и без известных аудиокодеков загрузка останавливается.
- До 1000 обнаруженных источников на вкладку; HLS — до 2000 сегментов. Прямой файл или весь HLS-поток — до 256 МБ. Файл собирается в оперативной памяти. Закрытие вкладки загрузки прерывает операцию. Сетевой запрос ограничен 30 секундами; медленная загрузка может завершиться ошибкой тайм-аута.
- Для записей из музыкального API название и исполнитель относятся к одному объекту с URL. Повторный ответ для тех же `owner_id`/`id` обновляет ссылку без дублирования записи; данные API имеют приоритет перед разметкой страницы. Для остальных источников остаётся название из разметки, недавнего нажатия или имени файла; при предварительной загрузке такой запасной вариант может быть неточным. Один трек может давать несколько отдельных источников. Сегменты AAC с явным расширением также могут появляться отдельно; для полного потока выбирай HLS.
- Ссылки могут истекать. Если сервер отказал в доступе, включи трек заново и обнови список. Сервер также может требовать заголовки или cookies, недоступные расширению.
- Если используется неподдерживаемое шифрование, ключ недоступен либо медиапоток не обнаружен, эта версия не скачает запись. Пустой или скрытый URL в API не мешает отдельно обнаружить явный URL потока при воспроизведении. Обычный обработчик страницы не видит запросы из Worker и других необработанных контекстов. Резервный режим получает только те ответы, которые доступны в Network; отсутствующий или удалённый из журнала ответ получить нельзя. Произвольные методы API не читаются. Лимит текстового ответа — 16 МБ; из одного ответа извлекается до 500 записей.
- Firefox в этой сборке не поддерживается.

Используй расширение для собственных записей и аудио, на сохранение которого у тебя есть разрешение. Доступ к закрытым записям и ограничениям подписки не обходится.

## Данные и разрешения

### HLS AES-128 — исправление 0.3.4

Версия 0.3.3 останавливала загрузку при любом `EXT-X-KEY` с методом кроме `NONE`, поэтому её сообщение о защите не определяло, был ли это AES-128 или DRM. Теперь поддержан `METHOD=AES-128` с `KEYFORMAT=identity` (или без KEYFORMAT). Ключ загружается по URI из плейлиста и должен содержать ровно 16 байт. Сегменты расшифровываются AES-CBC средствами Web Crypto с проверкой PKCS#7, затем проверяется их контейнер.

Поддержаны явный IV, IV из 64-битного `EXT-X-MEDIA-SEQUENCE`, смена ключа, в том числе при одинаковом URI в новом теге, и переход к незашифрованным сегментам через `METHOD=NONE`. Зашифрованный `EXT-X-MAP` требует явного IV. `SESSION-KEY` в master-плейлисте проверяется как подсказка; параметры сегментов берутся из конечного media-плейлиста.

Если ключ находится на другом сервере, вкладка загрузки предложит разрешить доступ. Ключи хранятся только в памяти текущей загрузки, не записываются в storage или диагностику; буферы ключей очищаются после попытки. HTTP-отказ, неправильный ключ или повреждённый сегмент останавливают сохранение. SAMPLE-AES и DRM имеют отдельное сообщение об отсутствии поддержки.

После обновления закрой старую вкладку с ошибкой и нажми «Скачать» заново. Вид шифрования конкретного пользовательского потока по старому сообщению определить нельзя; поддержка проверена на локальном AES-128-потоке.

Реализация следует [RFC 8216, EXT-X-KEY и правилам IV](https://www.rfc-editor.org/rfc/rfc8216#section-4.3.2.4) и использует [Web Crypto AES-CBC](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/decrypt).

### Разрешения

Обязательный доступ — страницы `vk.com`, `vk.ru`, аудиосерверы `vkuseraudio.ru` и поддомены этих трёх доменов, API загрузок, временное хранилище и `scripting` для обновления обработчиков страницы. Запросы аудио используют `credentials: include`; браузер применяет свои правила отправки cookies, расширение не читает cookies. DevTools-захват объявлен через `devtools_page`, разрешение `debugger` не используется.

В манифесте также объявлена возможность запросить HTTPS-доступ к другим серверам, если ссылка выходит за пределы перечисленных доменов. Для них разрешение запрашивается только на конкретные серверы выбранного файла или HLS-потока, в том числе для проверки прямого MP3. Выданные разрешения браузер сохраняет; их можно отозвать в настройках расширения.

Список источников хранится только в памяти вкладки. Задание загрузки кратковременно передаётся через `storage.session` и удаляется при открытии вкладки загрузки. Обработчики страницы и DevTools извлекают URL, идентификатор, исполнителя, название и длительность. В основной список и фоновый обработчик передаются только эти поля и безопасные счётчики диагностики. Полные ответы, `access_key`, `track_code`, заголовки авторизации и параметры запросов API не сохраняются и не отправляются на внешние серверы. Подписанная медиассылка сохраняется целиком для скачивания. Данные из контекста страницы проверяются; сообщение страницы не может самостоятельно запустить загрузку.

Нет аналитики, внешнего бэкенда, удалённых скриптов, массовой загрузки. Ссылки могут содержать временные ключи доступа — не публикуй их в отчётах об ошибках.

## Разработка и проверка

Для использования расширения Node.js не нужен. Для проверки и сборки нужен Node.js 22+:

```powershell
node scripts/check.mjs
node --test tests/media.test.mjs tests/hls.test.mjs tests/page-api.test.mjs tests/devtools.test.mjs tests/decoder.test.mjs tests/ts-audio.test.mjs tests/background.test.mjs tests/download.test.mjs
node scripts/package.mjs
```

Сборка запускает проверки и создаёт ZIP и файл SHA-256 в `artifacts/`. В архив входят только файлы расширения и эта инструкция. Проверки используют локальные данные и не требуют доступа к аккаунту VK. Никаких действий с телефоном, установки в браузер пользователя или публикации сборка не выполняет.

`node scripts/browser-smoke.mjs` дополнительно проверяет расширение в отдельном временном профиле Chrome: загрузку Manifest V3, поиск DOM-источников и HLS в Resource Timing, обнаружение названий и длительности в Fetch-ответе `catalog.getSection`, обновление подписанных ссылок через XHR без дублей, приоритет названия API перед DOM, список во всплывающем окне, ограничения сообщений и сохранение HLS по URL без расширения. Тест сам создаёт короткий звуковой сигнал через FFmpeg, подменяет ответы VK локальными данными, сравнивает извлечённое аудио с результатом независимого FFmpeg stream copy и декодирует результат через FFmpeg. Пути к Chrome и FFmpeg можно задать переменными `VK_TEST_BROWSER` и `VK_TEST_FFMPEG`. Отчёт — `artifacts/browser-smoke.json`. Обычный профиль браузера и аккаунт VK не используются; системный диалог выбора имени файла в этом тесте не проверяется.

Дополнительно проверяется сценарий «в al_audio.php нет подходящих URL, но M3U8 найден»: классификация причин, чтение Media Session из изолированного контекста, присвоение имени по кнопке, сохранение имени при смене песни и отказ при устаревшем выборе. Тест с `$env:VK_TEST_DEVTOOLS = '1'` также открывает настоящие DevTools в тестовом профиле и проверяет получение музыкального ответа из iframe с нативными Fetch/Response, где обработчики страницы не установлены. Отчёт — `artifacts/browser-devtools-smoke.json`. Перед обычной проверкой переменную можно убрать: `Remove-Item Env:VK_TEST_DEVTOOLS`.

Для 0.3.2 добавлены проверки структуры `messages.getHistory` из пользовательского примера (с тестовой медиассылкой): точное название, 198 секунд, MP3 с параметрами, экранированные слеши, пересланные сообщения и ответы, исключение текста/профилей/ключей. В Chrome проверяются обычный Fetch и независимый DevTools-захват истории из iframe, а также отображение названия, MP3 и 3:18 в popup. Действительная подписанная ссылка пользователя не запрашивается и в тестах не хранится.

Для 0.3.3 проверяются декодирование музыкальных массивов, сохранение параметров URL, зависимость от ID пользователя, ошибки формата и лимиты. В браузере проверяются именованные MP3/HLS из `al_audio.php`, обновление уже найденного HLS без дубликата и независимое декодирование через настоящие DevTools при запросе из iframe без обработчиков страницы.

Для 0.3.4 добавлены тесты IV и 64-битных номеров, смены ключей, METHOD=NONE, зашифрованного init, отказа для SAMPLE-AES/DRM, некорректных ключей и padding. Браузерная проверка сохраняет поток, независимо зашифрованный Node/OpenSSL; в 0.3.5 извлечённое из него аудио побайтно совпадает с независимым эталоном FFmpeg. Отдельно проверены отказ сервера ключей до загрузки сегментов и запрос разрешения для другого домена ключей.

Для 0.3.5 добавлены эталоны AAC и MP3 (MPEG-1/2/2.5), переносы таблиц и заголовков через границы пакетов, повторные пакеты, пропуски, повреждённые CRC, обрезанные кадры, отказ для MPEG Layer II и AAC LATM. Эталоны `tests/fixtures/ts` созданы из синусоидального сигнала скриптом `node scripts/generate-ts-fixtures.mjs`; FFmpeg нужен только для их регенерации и браузерной проверки. Обычные тесты Node.js читают готовые эталоны. Браузерная проверка дополнительно сохраняет MP3 из TS и убеждается, что повреждённый TS не создаёт загрузку.

Для 0.3.6 браузерная проверка добавляет строки после загрузки страницы, проверяет одинаковые названия с разными ID, позднее получение метаданных, смену ID строки, восстановление удалённой кнопки и блокировку программного клика. Доверенные клики мышью и Enter проходят полный путь до сохранения HLS; результат сравнивается с эталоном, счётчик событий воспроизведения строки остаётся нулевым. Тесты фонового обработчика отдельно проверяют исходный документ, прямые файлы, задания HLS, отказ без разрешения на нажатие и проверку URL.

Для 0.3.7 проверяются реальные MP3/AAC, большой ID3-тег, отказ для текстовых страниц и JSON без раскрытия содержимого. В Chrome проверены HTTP 200 с HTML/JSON под видом MP3, настоящий MP3 с заголовками HTML и именем `.htm`, HLS по адресу `.mp3`, а также ссылка, возвращающая аудио только при первом запросе. Проверяется ровно один GET по исходному адресу и побайтное совпадение сохранённого файла с проверенным аудио. Прямой MP3 также проходит весь путь от нажатия стрелки в строке до сохранения через Blob.
